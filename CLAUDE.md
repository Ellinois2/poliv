# CLAUDE.md — правила работы над «Полив»

## С чего начинать

- Перед любой работой прочитай `SPEC.md` — там продукт, решения и этапы.
- Эталон дизайна — `prototype.dc.html`: кликабельный прототип (разметка и логика в одном файле). Повторяй структуру, тексты и поведение экранов; цвета и размеры — из таблицы в `SPEC.md`.

## Как работаем

- Строго по этапам из `SPEC.md`. Делай только текущий этап.
- В конце этапа: собери APK в GitHub Actions, дай владелице ссылку на артефакт и короткий список того, что проверить на телефоне.
- Следующий этап начинаем только после её явного «зелёного света».
- Не меняй то, о чём не просили. Если требование противоречивое или неполное — сначала спроси.
- Коммиты небольшими шагами, сообщения по-русски и по делу.

## Общение с владелицей

- Она дизайнер, не разработчик. Пиши по-русски, просто, без канцелярита и технических подробностей, если она о них не спрашивает.
- Всё, что нужно сделать ей самой (настройки GitHub, телефона, RuStore), — пошагово, с точными названиями кнопок.
- Говори прямо, если решение приведёт к плохому результату, и предлагай альтернативу.
- Она любит уместные цитаты из «Властелина колец».

## Технические правила

- `applicationId` — **`ru.ellin.poliv`**. Не менять никогда.
- Kotlin, Jetpack Compose, Material 3 с собственной темой, Room, DataStore. Без лишних библиотек.
- **Без Google Play Services.** Телефон владелицы — Huawei Y8P (EMUI 10, Android 10), скорее всего без GMS. Не подключать Firebase, FCM, Google ML Kit, Google Sign-In, GMS-локацию и т. п. Распознавание речи — Vosk офлайн.
- `minSdk` 26.
- Уведомления — только локальные (AlarmManager / WorkManager), с перепланированием после перезагрузки.
- Тексты интерфейса — в `strings.xml` на русском; числа с правильными склонениями через `plurals`.
- Юнит-тесты обязательны для логики сроков (полив, подкормка, сезон, «зимой реже») и разбора голосовых фраз.

## Секреты

- Ключ подписи, пароли, токены — **никогда не коммитить**.
- В `.gitignore`: `*.jks`, `*.keystore`, `local.properties`, `keystore.properties`.
- Релизная подпись в CI — из GitHub Secrets: `KEYSTORE_BASE64`, `KEYSTORE_PASSWORD`, `KEY_ALIAS`, `KEY_PASSWORD`.
- Ключ хранит владелица (менеджер паролей и резервная копия). Потеря ключа = невозможность обновлять приложение в сторе; напомни ей об этом, когда создашь ключ.

## Сборка

- GitHub Actions: на каждый push в `main` — отладочный APK (артефакт сборки).
- Релизный подписанный APK/AAB — вручную или по тегу.
